# TP_Approval — постоянные инструкции

## Назначение и границы
Реальная система согласования актов технологического присоединения Сочинского ПЭС: документы, версии, замечания, маршруты, сроки, уведомления, аналитика и интеграции. Общаться исключительно на русском языке.

## Обязательное начало каждой сессии
1. Прочитать этот файл, `CONTEXT.md` (ключевые моменты, обновлять при значимых изменениях), `docs/PROJECT_CONTEXT.md`, `docs/PROGRESS.md`, `docs/IMPLEMENTATION_PLAN.md`, `docs/DECISIONS.md`.
2. Проверить текущий каталог, `git status --short --branch`, текущую ветку и последние коммиты. Для пустого репозитория отсутствие HEAD нормально.
3. Сопоставить фактический код с журналом; продолжать последний незавершённый шаг, не выдавая планы за реализацию.
4. Изучить вложенные AGENTS.md перед изменениями соответствующих каталогов.

## Безопасность
- JWT проверять на сервере; роли и область РЭС брать из собственной БД. Проверять права на каждый вложенный ресурс, файл, отчёт, экспорт и фоновое задание.
- RLS — дополнительная защита БД, runtime без superuser/BYPASSRLS/владения таблицами. Пользовательский контекст только в транзакции; не допускать утечки через пул соединений.
- Хранить файлы вне web-root, ограничивать загрузку, проверять содержимое и ZIP-структуру DOCX, карантин/антивирус, исключать SSRF, макросы и опасные внешние связи. Решение владельца 05.11.2026: внешние связи бланков (гиперссылки, шаблоны, источники слияния) игнорируются — сервер и просмотр по ним не обращаются; встроенные схемы Visio (.vsdx/.vsd) допустимы; макросы, ActiveX и прочие вложения запрещены.
- Не помещать в Git секреты, JWT, ПДн, реальные DOCX/PDF, дампы, резервные копии, виртуальные окружения. Не передавать ПДн внешним AI API без отдельного разрешения и политики.
- Исходные и поданные версии неизменяемы; решения и аудит сохраняются. Электронное согласование не является ЭП.
