# Режим проверки документов — 04.11.2026

Эталон: [design/target-review-mode.png](design/target-review-mode.png). Открывается кнопкой «Режим проверки» в шапке документа (`apps/web/src/ReviewMode.tsx`, стили `review.css`), рисуется порталом в `body` поверх приложения.

## Устройство
- **Слева — проверяемый документ** (Акт ТП / АВТУ, выбор версии). Только к нему можно оставить замечание: выделить фрагмент → «+ Добавить замечание».
- **Справа — документ для сравнения, только просмотр:** редакции ТУ договора (по умолчанию те, по которым идёт сверка) или другие версии этого же акта.
- **Синхронная прокрутка** — прокрутка одного окна двигает другое пропорционально (`DocumentViewer.scrollToRatio` / `onScrollRatio`).
- **Панель справа:** вкладка «Замечания» (Открытые/Устранённые, переход к фрагменту, подтверждение или отклонение исправления автором замечания) и вкладка «Сверка с ТУ» (автосверка). Расхождения и неподтверждённые спорные пункты подсвечиваются жёлтым в обоих окнах (`highlightBlocks`), клик по значению ведёт к абзацу в нужном окне.
- **Роли:** инженер РИРУ до отправки только сверяет (запуск сверки, ручное подтверждение спорных пунктов, «Отправить на согласование»), замечаний не пишет — решение пользователя 04.11.2026. Согласующий с открытой задачей пишет замечания и принимает решение («Вернуть» / «Согласовать» через тот же DecisionDialog). Остальные — просмотр.
- Бизнес-логика маршрута, API и правила сверки не менялись: режим использует существующие эндпоинты.

## Проверка
`npm run test:review:browser` — настоящий Chromium на изолированной БД: импорт ТУ с карточкой, подсветка расхождения в обоих окнах, отправка исправленной версии из режима, замечание начальника РИРУ к выделенному фрагменту, вёрстка на телефоне. Отчёт и снимки — `.local/review-browser-report`.
