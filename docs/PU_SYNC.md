# Синхронизация с «Учёт ПУ»

Решение владельца 09.11.2026. «Учёт ПУ» по номеру договора ТП забирает из ТП Согласования РЭС, реквизиты и технические характеристики. Это поля карточки документа, которые заполняются из ТУ. После переноса «Учёт ПУ» ставит отметку «синхронизирован». Отметка видна в обеих программах.

Сторона «Учёт ПУ» пока не дорабатывается. Ниже — готовый контракт, к которому она подключится.

## Что хранится

- Данные не копируются, они берутся из актов. На один номер договора приходится одна строка: акт ТП, а если его нет — АВТУ. Если документов этого вида несколько, берётся последний созданный (`app.pu_sync_rows`).
- `app.pu_sync` (миграция 030) хранит только отметку: номер договора, хеш переданных данных, внешний id в «Учёт ПУ», время первой и последней синхронизации, число синхронизаций.
- Статусы:
  - `NOT_SYNCED` — договор ещё не забирали;
  - `SYNCED` — забраны актуальные данные;
  - `CHANGED` — после синхронизации поменялись реквизиты, карточка или ТУ, нужно забрать повторно.

## Рабочее место

- Меню «Синхронизация» видно всем ролям.
- Вкладки: Все / Не синхронизированы / Синхронизированы / Изменены после синхронизации. Есть поиск по номеру, заявителю и адресу и фильтр по РЭС.
- Строки ограничены областью пользователя (`can_read` или инженер своего РЭС).
- В шапке документа показывается метка «Учёт ПУ: синхронизирован» или «изменён после синхронизации».
- API рабочего места: `GET /api/v1/sync?status=&q=&res=&page=&limit=`.

## Сервисный API для «Учёт ПУ»

Пользовательский вход не нужен. Ключ передаётся в заголовке `X-Sync-Key: <SYNC_API_KEY>`. Ключ задаётся переменной окружения `SYNC_API_KEY` (не короче 32 символов). Без неё API отвечает `503 SYNC_NOT_CONFIGURED`, при неверном ключе — `401 SYNC_KEY_INVALID`.

| Запрос | Ответ |
|---|---|
| `GET /sync/v1/res` | `[{code,name}]` — РЭС для сопоставления |
| `GET /sync/v1/contracts?res=<code>&q=&status=NOT_SYNCED\|SYNCED\|CHANGED\|all&page=&limit≤200` | `{items,counts,total,page,limit}` — список по РЭС и поиску |
| `GET /sync/v1/contracts/<номер>` | один договор; `404 CONTRACT_NOT_FOUND`, `422` — неверный формат номера |
| `POST /sync/v1/contracts/<номер>/synced` `{hash, externalId?}` | отметка «синхронизирован»; `409 SYNC_STALE`, если данные изменились после чтения |

Договор в ответе:

```json
{"contractNumber":"00001-26-00000004-1","contractDate":"2026-11-02","res":{"code":"...","name":"Адлерский РЭС"},
 "applicant":"...","address":"...","documentType":"ACT_TP","documentState":"DRAFT","approved":false,
 "tu":{"revision":1,"number":"...","date":"2026-10-01"},
 "technical":{"power_kw":{"label":"Максимальная мощность","value":"15","unit":"кВт","origin":"TU"},"voltage_kv":{...},"phases":{...},"plan_date":{...}},
 "hash":"<md5>","sync":{"status":"NOT_SYNCED","syncedAt":null,"count":null,"externalId":null}}
```

Порядок работы «Учёт ПУ»:

1. Прочитать договор и запомнить `hash`.
2. Перенести данные к себе.
3. Отправить `POST …/synced` с этим `hash`.
4. На `409` — перечитать договор и повторить.

Значения `technical` — строки, как в карточке: десятичная точка, `phases` — `1ф`/`3ф`/`3фтт`. Состав полей определяет администратор в «Полях карточки», код поля служит ключом.
