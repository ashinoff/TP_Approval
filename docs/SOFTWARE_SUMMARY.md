# TP_Approval — краткое содержание ПО

Веб-приложение Сочинского ПЭС для подготовки и согласования актов технологического присоединения. Деловой ключ пакета документов — номер договора ТП. Пакет включает ТУ и акт ТП либо АВТУ; файлы, редакции и циклы имеют собственные технические UUID и неизменяемую историю.

Инженер РИРУ своего РЭС создаёт документ, загружает ТУ и акт, проверяет извлечённые реквизиты и соответствие ТУ. Новый документ получает номер договора; неизвестные реквизиты не выдумываются и не блокируют сохранение черновика. Неизвестная дата договора хранится как NULL, отдельно от даты создания. Затем выполняются обязательная проверка и отправка на согласование.

Маршрут: **Инженер РИРУ → Начальник РИРУ своего РЭС → Начальник РЭС → параллельно СТП, СУЭ и ТЕХБЛОК**. Возврат одной центральной службы не завершает проверки остальных. Исправленная версия проходит полный новый цикл, предыдущие решения не переносятся; устранение замечаний подтверждает их автор. Запрещены самосогласование и решения одного человека в разных ролях по одному акту; предусмотрено датированное замещение.

Реализованы персональные очереди, реестр, единое рабочее место акта, просмотр DOCX/ТУ, визуальные замечания к фрагментам, версии, сравнение текста, матрица и история согласования, уведомления, badge по уникальным документам с действием, сроки/просрочки/эскалации, утверждённые публикации и пересмотр. Непрочитанные уведомления считаются отдельно от задач.

Стек: React/Vite/TypeScript, Node.js/Express, PostgreSQL с миграциями и RLS, приватное файловое хранилище. JWT проверяется сервером, роли/РЭС хранятся в БД. Отдельные технический и процессный администраторы. SUE_system остаётся внешней оболочкой; бизнес-логика находится здесь. Боевой Keycloak/Amvera не подключены.

ТУ распознаются локально правилами без внешних ИИ. Импорт из формы безопасно удаляет только ссылку attachedTemplate на локальный file-шаблон, показывает уведомление и повторно проверяет результат; прочие внешние ресурсы, макросы и небезопасные пакеты отклоняются. Исходник на компьютере не изменяется. Проверка перед согласованием ограничена пятью реквизитами, UNKNOWN/MANUAL_REVIEW блокируют отправку; ручной обход не реализован.

Ограничения: docx-preview — приблизительный просмотр, не точная вёрстка/редактирование Word. ONLYOFFICE, PDF/OCR, надёжная печать, полноценная интеграция с программой учёта ПУ, схема/ПСУ/прочие вложения ещё не завершены. Производственная эксплуатация требует настройки SSO, антивируса, календаря, резервных копий и проверки реальных обезличенных шаблонов. Электронное согласование не является ЭП.

Локальный стенд: `npm ci`, `npm run demo`; интерфейс http://127.0.0.1:5173, API http://127.0.0.1:3000/ready. Используется отдельная тестовая PostgreSQL и локальная подписанная JWT-авторизация. Инженер: «Инженер РИРУ · Адлерский РЭС» (riru-adler). Остановка: `npm run demo:stop`. Данные/ключи/документы стенда исключены из Git.

Для продолжения разработки обязательно читать **AGENTS.md**, **PROJECT_CONTEXT.md**, **PROGRESS.md**, **IMPLEMENTATION_PLAN.md**, **DECISIONS.md**, затем проверять Git. Последние изменения интерфейса описаны в TU_IMPORT.md; фактические результаты проверок и незавершённые задачи — в начале PROGRESS.md. Старые записи журнала не заменяют актуальное состояние.
