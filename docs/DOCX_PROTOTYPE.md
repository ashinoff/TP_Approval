# Интерактивный DOCX: технический прототип — 01.11.2026

## Статус и выбранный подход
**Это проверенный локальный прототип, а не завершённый точный Word-просмотр.** ONLYOFFICE не установлен и не запускался. Проверка команд/путей не обнаружила Docker, WSL, ONLYOFFICE Docs, Word или LibreOffice. Пользователю отправлен вопрос о наличии своего локального Document Server; адрес пока не предоставлен. Системное ПО не устанавливалось. Внешние документы/ПДн никуда не передавались.

Основной кандидат для точной вёрстки остаётся локальный ONLYOFFICE Docs. Его [Automation API](https://api.onlyoffice.com/docs/docs-api/usage-api/automation-api/) для управления комментариями из внешней панели доступен только Docs Developer, за дополнительную плату. Нельзя обещать createConnector в Community. Вариант Community с собственным плагином требует отдельной проверки Plugin API и поведения комментариев в режиме запрета редактирования. [Лицензионный FAQ Community](https://helpcenter.onlyoffice.com/docs/faq/docs-community.aspx) и [сравнение редакций](https://www.onlyoffice.com/compare-editions) необходимо оценивать для выбранной закреплённой версии и способа распространения приложения; юридическое заключение/приобретение лицензии не выполнены. Пределы соединений нельзя переносить между версиями по старым статьям.

Для проверки привязок без установки системных служб реализован docx-preview 0.3.7 (Apache-2.0), локальная библиотека. [Официальный README](https://github.com/VolodymyrBaydalka/docxjs) прямо ограничивает её HTML-возможностями: нет полноценной автоматической пагинации и вычисления полей. Поэтому вариант помечен «Технический прототип» в интерфейсе, не принят как замена ONLYOFFICE для промышленного точного просмотра. Библиотеки не загружаются с CDN; DOCX обрабатывается локальным браузером, извлечение текстовых якорей/сравнение — своим API.

## Проверить самостоятельно
1. Открыть http://127.0.0.1:5173, войти РИРУ Адлерского РЭС. Поиск `WORD-` находит тестовые акты; последний завершённый пример — `.local/document-report/result.json` (только синтетика).
2. Открыть карточку → **«Документ»**. Соседняя вкладка «Документ и замечания» сохраняет прежнюю загрузку версий/формы. Выбрать v1/v2, масштаб, страницу и поиск по тексту.
3. Для нового сценария создать карточку, загрузить `.local/demo-documents/complex-v1.docx`, отправить РЭС; войти начальником Адлерского РЭС и согласовать.
4. Войти СУЭ/СТП/ГИ с активной задачей. Во вкладке «Документ» выделить `150 кВт` внутри одного абзаца. «Добавить замечание» → категория «Ошибка в мощности» → описание → предложить `15 кВт` → сохранить. Панель и красный маркер связаны в обе стороны.
5. Несколько замечаний можно сохранить до решения. Согласование с собственными визуальными замечаниями текущей версии блокируется; возврат требует причины. Другие центральные подразделения продолжают проверять.
6. После завершения сбора войти РИРУ, загрузить complex-v2.docx через прежнюю вкладку. Во вкладке «Документ», выбрав v2, сообщить об исправлении каждого замечания. Подать новую версию, снова согласовать РЭС.
7. Автор замечания при своей новой задаче выбирает v2, сравнивает редакции, подтверждает либо отклоняет исправление с объяснением. В старую версию можно перейти отдельно. Автопереноса маркеров нет.
8. Только после проверок всех авторов и четырёх согласований появляется утверждённая публикация. Скачать оригинал можно всегда в пределах прав; **чистовая и служебная печать недоступны** до внедрения проверенного генератора.

Создать DOCX заново: `C:\Users\User\codex\.venv\Scripts\python.exe scripts/create-document-fixtures.py`. В Docker/серверное окружение этот скрипт пока не включён: это генератор тестовых файлов разработчика, не сервис документов.

## Данные, безопасность, API
Миграции 007/008 добавляют 12 категорий и поля comments: category_id/name (снимок), anchor, original_value, suggested_value, discussion, author_snapshot. Старые общие замечания поддерживаются без anchor. Новые замечания связаны с существующими act/version/task; task однозначно задаёт cycle/department/stage. Исходные файлы и версии не пересохраняются. Комментарии и correction events append-only. Непрочитанные уведомления/badge не менялись.

- `GET /api/v1/error-categories`; `POST /api/v1/admin/error-categories` — TECH_ADMIN через проверенную SECURITY DEFINER функцию с аудитом, без доступа к актам.
- `GET /api/v1/acts/{act}/versions/{version}/preview` — фактические блоки OOXML, хеши, ограничения. Аудит DOCUMENT_VIEWED.
- `POST /api/v1/acts/{act}/comments` — versionId, taskId, categoryId, text, suggestedValue, discussion, anchor. Idempotency-Key обязателен. Блокировка акта сериализует комментарии с решениями; только эффективный согласующий открытой задачи/версии, запрет самосогласования/конфликта ролей. Проверяются точные байты, абзац и диапазон, не принимается произвольная цитата клиента.
- anchor `OOXML_PARAGRAPH_V1`: part, blockId, blockHash, fileHash, start/end (UTF-16), quote. Привязка внутри одного однозначно сопоставленного абзаца, включая ячейку. Повторяющиеся/несопоставимые абзацы в прототипе не разрешают выделение. Перенос диапазона между абзацами/рисунками не реализован.
- `POST /api/v1/comments/{id}/events` — прежний API REPORTED_FIXED/VERIFIED/REOPENED и объяснение. Статусы UI: Не исправлено / Исправлено, ожидает проверки / Подтверждено / Исправление отклонено. Подтверждать/отклонять может автор при активной новой задаче. История объяснений сохранена; отдельного свободного чата нет.
- `GET /api/v1/acts/{act}/compare?from={version}&to={version}` — diff слов с удалением/добавлением, изменения снимка реквизитов, статусы замечаний. Ограничение 200000 суммарных символов, 1 секунда алгоритма/20000 edit length. Геометрия таблиц/стили/рисунки не сравниваются. Аудит DOCUMENT_COMPARED.
- Просмотры, сравнения, скачивания и создание замечаний проверяются сервером/RLS; TECH_ADMIN и чужой РЭС получают 404. Файлы доступны только Bearer API, открытых статических ссылок нет. Скачивание пишет DOCUMENT_DOWNLOADED. Исходный SHA-256 проверяется при чтении.

Просмотр в iframe sandbox без allow-scripts; CSP default-src none, только встроенные стили и локальные data/blob изображения/шрифты. DOM очищается DOMPurify; внешние связи отклоняет действующий валидатор DOCX, altChunk отключён. Стили изолированы от приложения. Исправлены новые зависимости до diff 8.0.4/DOMPurify 3.4.17; npm audit после установки — 0 известных уязвимостей. ClamAV в dev по-прежнему не запущен; production требует его по прежнему правилу.

## Что реально проверено
Нативный PostgreSQL 17.11, настоящий headless Chrome 156 и созданные python-docx бинарные complex-v1/v2 с таблицей, горизонтальными/вертикальными объединениями, колонтитулами, нумерованным списком, отступом, разноформатными runs, полем PAGE и ручным разрывом. Таблица/объединения/текст колонтитулов/две страницы и интерактивные замечания проверены; скриншоты просмотрены. **Соответствие Word pixel-to-pixel, расчёт PAGE, автоматические разрывы и реальные обезличенные акты не проверены.** Это существенное ограничение кандидата, не успешный fidelity-тест.

Команды: `npm test`, `npm run test:integration`, `npm run test:documents:browser`; прежние browser/matrix/registry suites. Отчёты `.local/document-report` вне Git. Последние фактические результаты — PROGRESS.md.
