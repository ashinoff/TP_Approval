# Концепция проверки акта ТП

Основа — шаблон владельца `15 кВ ПАО от РУ на бумаге.xlsx` (07.11.2026, файл в Git не хранится). Акт собирается
из листа «ФОРМА»: инженер вводит переменные один раз, формулы разносят их по акту. Постоянный текст (п. 8.1–8.6,
подписанты) от акта к акту не меняется. **Схема — встроенный рисунок, её правят руками**: чаще всего ошибка там
(в шаблоне лежала схема прежнего акта: «фидер «Альпийская», ТП-47, ВА 25 А» рядом с текущей «ТП-176, ВА 40 А»).

## Слои проверки

1. **Акт ↔ ТУ** (`tu-rules.ts`): договор, мощности, напряжение, адрес, точка, заявитель, ТП, питающий центр, пункты ТУ.
2. **Номиналы** (`nominal-rules.ts`): ВА, ТТ, сечение по справочникам.
3. **Сам акт** (`act-rules.ts`):
   - постоянные пункты: 8.2 — «Сетевая организация»; 8.1 — Заявитель/Сетевая, подтверждает человек;
   - **единообразие**: ТП, фидер, опора, провод, длина, ВРУ (0,22 = 0,23 кВ), ВА — одно значение во всех местах
     акта и на схеме. Синий — одинаково; разные значения — «проверить вручную» (обычно схема от прежнего акта);
   - **схема ↔ текст**: элементы у красной границы по сторонам (сеть / заявитель) против описания границы и таблиц
     оборудования; **место границы по рисунку** (кружок опоры / рамка ТП-РУ-ВУ / рамка ВРУ) против «…от X сетевой
     организации». Граница — прямая красная линия или точка схождения двух красных стрелок (второй вид пока
     не проверен на реальном PDF).

Цвета в просмотре: зелёный — совпало с ТУ (одно место), синий — то же значение в остальных местах акта,
красный — расхождение, жёлтый — проверить вручную; место границы на схеме обводится пунктирной рамкой.

## Следующие шаги (не сделано)
- Арифметика: всего = существующая + присоединяемая; категория III = всего; мощность в таблице точек = всего;
  «7,0 (семь) кВт» — число и пропись.
- Схема: «Р = … кВт» и ФИО заявителя («Герун Ж.И.») против текста; счётчик по сторонам границы против п. 8.5.
- Граница-стрелки: проверить на PDF актов «от РУ» и «от опоры» (нужны PDF от владельца).
