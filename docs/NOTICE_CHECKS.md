# Проверка уведомления об обеспечении возможности присоединения

Основа — разбор владельца от 09.11.2026 (файл `Логики проверок/промт.docx`). Пример: уведомление ООО «Славяне», ТП-А86. В этом примере прибор учёта стоит в ВРУ заявителя. PDF в Git не хранятся.

Следующие этапы разбора у владельца:

- уведомление с ПУ сплит-исполнения на опоре;
- акт ТП.

## Вид документа

Кнопок «Акт ТП / АВТУ» больше нет. Вид определяется по заголовку (`document-kind.ts`, `POST /api/v1/documents/inspect`):

| Заголовок | Вид |
|---|---|
| АКТ об осуществлении технологического присоединения | `ACT_TP` |
| УВЕДОМЛЕНИЕ об обеспечении сетевой организацией возможности присоединения к электрическим сетям | `NOTICE` (миграция 031) |
| АКТ О ВЫПОЛНЕНИИ ТЕХНИЧЕСКИХ УСЛОВИЙ | `AVTU` |

- Если заголовка нет, вид определяется по фразам текста («Настоящее уведомление составлено…» и т. п.). Если не распознан и так, по умолчанию ставится акт ТП, и инженер может поправить вид.
- Скреплённый PDF делится автоматически:
  - страница с заголовком начинает новый документ;
  - страница без заголовка продолжает предыдущий;
  - расчёт потерь относится к акту ТП или уведомлению.
- Каждая часть сохраняется отдельным документом своего вида. Сервер вырезает страницы своей части (`pages` при загрузке файла).
- ТУ одна на договор: она загружается в основной документ, остальные ссылаются на ту же редакцию.
- Дата и номер договора берутся из документа, если их нет в ТУ.

## Проверки (`notice-rules.ts`, только для `NOTICE`)

Дополняют общую сверку с ТУ (`tu-rules.ts`): договор, заявитель, номер ТУ, наименование ЭПУ, адрес, мощности, напряжение, ПС, точка, ТП. Также дополняют номиналы и проверки границы на схеме (`act-rules.ts`).

| Поле | Что проверяется |
|---|---|
| `attorney` | доверенность из преамбулы — по справочнику «Доверенности»: номер, дата, ФИО подписанта (с учётом падежа), срок действия. Пустой справочник — ручная проверка |
| `contractDate` | «по договору … от ДД.ММ.ГГГГ» против даты договора в карточке |
| `powerSum` | всего = присоединяемая + ранее присоединённая |
| `powerEverywhere` | та же мощность в категориях надёжности (I+II+III), таблице точек и на схеме («Р = … кВт») |
| `transformers` | кВА трансформаторов: характеристики = таблица точек |
| `tg` | tg φ в таблице точек — по справочнику «tg φ» для её напряжения (0,4 кВ → 0,35) |
| `meterNetwork` | по ТУ (п. 10.x) учёт организует сетевая организация — прибор учёта должен быть в её оборудовании в п. 3 |
| `psu` | п. 4: ПСУ загружен к договору; в отчёте кнопка «Открыть ПСУ» |
| `breakerTu` | п. 5: ТУ требуют автомат (п. 11.x) — автомат указан; номинал проверяется отдельно, по справочнику |
| `reserve` | п. 6 «не требуется» против п. 9 ТУ «нет» |
| `losses` | п. 7 «расчёт потерь прилагается» — таблица расчёта есть в документе |
| `sealsParty` | п. 8.1 по схеме: Wh ниже границы (сторона заявителя) — «Заявитель», выше — «Сетевая организация». Заменяет общий вопрос «подтвердите сторону» |
| `meterPlace` | п. 8.5 по схеме: Wh ниже надписи «ВРУ… Заявителя» — «ВРУ»; между границей и ВРУ — «опора/ВЛ» (сплит-исполнение, правило предварительное); у сети — ТП/РУ/ВУ/опора |

Тот же номер ТУ теперь читается с буквенным хвостом («-сс», «сс/у», «-вд») и из фразы «согласно техническим условиям от …». Версия правил — `DOCX_CONTEXT_V9`.

## Справочники

Хранятся в `app.reference_books`, редактирует администратор во вкладках «Справочников»:

- `tg` — tg φ по уровню напряжения. По умолчанию 0,23/0,4 кВ → 0,35; 6–35 кВ → 0,4; 110 кВ → 0,5 (по приказу Минэнерго № 380). Администратор может поправить.
- `attorneys` — доверенности подписантов. Изначально пуст: персональные данные в миграцию не кладутся.

Ревизии справочников входят в версию отчёта сверки.
